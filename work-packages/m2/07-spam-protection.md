  `recentReportCount(...) > SUSPICION_MAX (3)` within `SUSPICION_WINDOW_MS (10 min)`
- `SUSPICION_MAX = 3`, `SUSPICION_WINDOW_MS = 10 * 60 * 1000`

## Task

`specs/06-report-form.md` §7.6 defers the per-IP / per-token rate limit and the
"suspicious" rule to this package. There is no cache or Redis in the stack
(`PLAN.md` §4), so the 10-minute window lives in PostgreSQL, the only shared
store. This package adds that storage and the detection helpers only; the honeypot
field, the Altcha challenge and the write of `tickets.suspected_spam` are the
child packages announced in the handoff.

1. `apps/api/src/db/schema.ts`: add `reportThrottle = pgTable('report_throttle', …)`
   with the columns and the two `(…, created_at)` indexes above; an append-only
   counter table, never updated or deleted by the application.
2. `npm run db:generate -w @stoerdesk/api` → migration
   `0005_report_throttle.sql`; keep it to the `CREATE TABLE` and the two indexes.
3. `apps/api/src/tickets/spam.ts`: `recordReportAttempt`, `recentReportCount` and
   `isReportSuspicious` with the two constants; the count is `count(*)` filtered by
   `created_at >= now() - window`, and the token and IP counts take the maximum.
4. Test `apps/api/src/tickets/__tests__/spam.integration.spec.ts`: three attempts
   are not suspicious, the fourth is; a fourth attempt for a **different** IP but the
   **same** token is suspicious (per-token rule), and vice versa (per-IP rule); an
   attempt outside the 10-minute window never tips the count.

## Non-goals

- No honeypot field, no Altcha, no change to the create path or
  `tickets.suspected_spam` — those are **WP-M2-07b/07c/07d**.
- No `@fastify/rate-limit` change: the global `RATE_LIMIT_MAX` stays as-is.
- No retention/purge job for `report_throttle` (rows are tiny; a cleanup can be a
  later phase, `PLAN.md` §15).
- No IP anonymization decision — see the open question.
