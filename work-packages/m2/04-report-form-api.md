## Deviation from the legacy plan

The legacy `04-report-form-api.md` mixed five layers (route, service, idempotency,
rate limit, tests) in one package and referenced the §-sections of two placeholder
spec slices. `PLAN.md` §17 forbids that size, so the package is split:
**WP-M2-04** (this one — tables, migration, counter), **WP-M2-04b** (public
`POST /api/v1/public/tickets` with idempotency) and **WP-M2-04c** (photo files and
`ticket_photos`). The **rate limit per IP and per QR token moves to the existing
WP-M2-07** (spam protection), which already defines "suspicious" and the
`suspected_spam` flag — see `specs/06-report-form.md` §7.6. The spec slices are
filled and reviewed first (`docs(spec)` commit of this package).

## Task

1. `apps/api/src/db/schema.ts`: add `tickets` per §4.8 — UUID v7 `id`, `ticketNo`
   with `.default(sql\`next_ticket_no()\`)`, `objectId` FK `ON DELETE RESTRICT`,
   `systemId` nullable FK `ON DELETE SET NULL`, `status`/`priority`/`source` checks
   over the values of `PLAN.md` §7 and §13, `faultTemplateKeys` as
   `text('fault_template_keys').array()`, the timestamps `reportedAt`,
   `receivedAt`, `deadlineAt`, the flags `clockSkewed` and `suspectedSpam`,
   `reporter*`, `clientUuid` (unique), `statusToken` (unique), `parentTicketId`
   self-FK `ON DELETE SET NULL`, and the five indexes of §4.8.
2. Same file: `ticketEvents` (§4.9, no `updatedAt`, `actorKind` check,
   `payload` jsonb default `{}`), `ticketPhotos` (§4.10, `filePath` unique,
   `mimeType` check, `sizeBytes`, `widthPx`/`heightPx`, `uploaderUserId`) and
   `ticketNoCounters` (§4.11, composite `year` primary key). Export the inferred
   types in the existing `export type …` block.
3. Run `npm run db:generate -w @stoerdesk/api`, then hand-append to
   `0004_ticket_tables.sql`: `CREATE OR REPLACE FUNCTION next_ticket_no()` and
   `CREATE OR REPLACE FUNCTION ticket_events_append_only()` plus
   `CREATE TRIGGER ticket_events_append_only BEFORE UPDATE OR DELETE ON
   "ticket_events"` — the append-only rule of `PLAN.md` §15, same style as the
   `protect_system_roles` trigger of migration 0001.
4. Test (fixture, outside the file budget):
   `apps/api/src/db/__tests__/ticketTables.integration.spec.ts` against a
   throwaway database — the migration creates the four tables and the two
   functions; five concurrent inserts produce five distinct
   `ST-<year>-NNNN` numbers; a second row with the same `client_uuid` violates
   the unique index; an unknown `status` and a bad `source` are rejected by the
   checks; `UPDATE`/`DELETE` on `ticket_events` raise
   `ticket_event_append_only`; deleting an object with tickets is refused
   (`RESTRICT`) while deleting a system sets `system_id` to `NULL`.

## Non-goals

- No API route, no Zod schema, no service function — WP-M2-04b.
