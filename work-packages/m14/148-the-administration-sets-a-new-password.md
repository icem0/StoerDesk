## Task

**The comment of the office (out of band in phase 14).** „bei der
benutzerverwaltung fehlt eine funktion .. neues passwort festlegen .. dabei soll
ein zufallspasswort erzeugt werden welches ein einmalpasswort ist das in die
zwischenablage kopiert wird sodass man es dem kollegen geben kann .. bei der
anmeldung mit dem neuen passwort muss der kollege aber ein neues, eigenes,
geheimes eingeben".

The administration sets the password of a colleague. The server generates it, so
the office knows no secret of the colleague; the colleague replaces it at the
first login with a secret of his own.

ADR-0031 decides the shape: the one-time password is a flag on the account, the
answer of the reset carries the plaintext exactly once, the block while the
flag is set is a rule of the guards and not of the client, and the sessions die
with the secret.

The decision splits into six packages:

1. **WP-M14-148a** — the database: the column `users.must_change_password`.
2. **WP-M14-148b** — the shared contracts: the flag in the answers, the answer
   of the reset.
3. **WP-M14-148c** — the session: the flag is read per request, the guards
   block the app, the own password clears the flag.
4. **WP-M14-148d** — the API: the administration sets the one-time password.
5. **WP-M14-148e** — the web: the colleague sets his own password.
6. **WP-M14-148f** — the web: the administration hands the one-time password
   over.

This package writes no product code.

## Non-goals

- No password reset by e-mail, no link with a token, no password policy beyond
  the minimum length of 12 characters (ADR-0031).
- No audit trail of the password changes (§3.5).
- No change of the login itself: the login answers the same way, it carries the
  flag.
